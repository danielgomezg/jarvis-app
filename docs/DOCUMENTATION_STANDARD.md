# Estándar de documentación

Todos los documentos deben cumplir las siguientes reglas.

- Usar Markdown.
- No escribir texto ambiguo.
- Explicar el "por qué", no solo el "qué".
- Pensar que otro desarrollador leerá el archivo dentro de un año.
- Siempre indicar dependencias.
- Siempre indicar el estado.
- Siempre indicar cuándo corresponde implementar algo.
- Evitar duplicar información existente.
- Si existe una decisión relacionada, enlazar el ADR correspondiente.

Toda documentación debe tener:

Objetivo

Contexto

Dependencias

Estado

Última actualización

Referencias

No duplicar información.

Explicar el porqué.

No escribir más de lo necesario.

Usar Markdown.
